# task-governance-tool v0.11.0

`task-governance-tool` 0.11.0 is the current unpublished local candidate. It
has not been pushed, tagged, published, or attached to a GitHub
Release, and this note grants no authority for any such external operation.
The immutable published v0.10.0 artifact and its publication record remain
unchanged.

## Candidate Identity

- SQLite schema: v17
- Viewer snapshot: v4, accepting source schemas v5-v17
- Public CLI: exactly 21 command leaves
- Supported runtime: Windows with Python 3.12 or newer
- CI workflow/name/job: `.github/workflows/ci.yml` / `CI` / `test`
- CI Python matrix: 3.12 and 3.14
- Remote/repository: `origin` / `VAiring/task-governance-tool`
- Publication state: unpublished local candidate; no candidate commit, tag,
  archive, checksum, or GitHub Release has been fixed

## Candidate Changes

- Schema v17 adds immutable, caller-attested Verification Receipts bound to
  the current Task Contract, verification expectation, and review-target
  generation.
- A nonempty verification expectation now requires one exact-current `pass`
  Receipt with `full` scope coverage before completion. Stale, partial,
  failed, timed-out, or inconsistent evidence fails closed.
- `taskgov verification receipt add` is the sole new public leaf. It records
  bounded facts supplied by the caller and never executes a project command.
- `task show --json` exposes the bounded current verification-evidence gate;
  existing text output remains unchanged.
- Viewer snapshot content remains v4 and accepts source schemas v5-v17. It
  performs internal completion-cycle link validation without adding Receipt
  data or controls to the Viewer.

## Privacy And Local-Only Boundary

Verification Receipt retention is deny-by-default. The candidate stores only
the sanitized command label, closed result, duration, full/partial coverage,
Task and Contract ownership, exact target basis, and recording time. It never
stores or executes the verification command body or arguments and never
retains exit code, stdout/stderr, stack trace, environment, logs, exceptions,
prompts, diffs, credentials, arbitrary coverage prose, or debug variants.

The Skill remains project-scoped, local-first, and standard-library-only. It
does not mutate target-project files or Git state, use a network service,
create an external Issue or PR, launch a browser, or grant publication
authority.

## Candidate Validation Boundary

The candidate is not a published release until its own exact target passes the
offline release checker, test-lane partition and full suite, schema-v1-through-
v17 migration and reentry checks, privacy and concurrency matrices, Viewer
compatibility, isolated physical install and upgrade/paired-rollback rehearsal,
two required Tier 2 reviews, and any separately authorized external release
process. Prior v0.10.0 evidence cannot satisfy this candidate's gates.
