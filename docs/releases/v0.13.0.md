# task-governance-tool v0.13.0

`task-governance-tool` 0.13.0 is the current unpublished local candidate. It
has no fixed exact final candidate commit, tag, archive, checksum, or GitHub
Release identity. An ordinary push to `main` is CI input, not release
publication, and this note grants no authority for any external release
operation. The immutable published v0.10.0 artifact and the immutable v0.11.0
and v0.12.0 candidate-lineage notes remain unchanged.

## Candidate Behavior

- Schema v25 adds actual-reviewer bindings to the existing core Receipt writer.
  Unchanged original handoffs carry machine metadata; no new LLM-entered field
  or registration step is required. Old Receipts and sealed Bundles stay intact.
  Explicit setup also advances the separate numerical store to schema 3 for
  inclusive-turn attribution and immutable cycle-linked usage snapshots.
  Late observations append successors and original-cycle links without changing
  completed Tasks or Bundles. Detail adds observed shared-work usage; completion
  acknowledges pending usage without accessing the numerical store. Optional
  [trusted project-local hooks](../setup-state-specification.md#optional-lifecycle-usage-collection)
  collect registered participants and catch up late records at later project
  events; setup prepares project-local definitions, but the user reviews/trusts
  them separately. Preparation never claims collection is enabled. No normal-loop command or gate is
  added, and Stop never certifies final usage coverage. Host delivery/format
  support requires its own isolated observation, not an all-platform assumption.
  The hook's optional `--repo <project-root>` enables the existing development
  self-host layout only when it matches process cwd; ordinary installs need no
  extra argument and all physical-layout checks remain in force.
- Schema v24 adds automatic session ownership and execution/cycle linkage.
  Active work occupies one caller/project slot; review-pending keeps completion
  responsibility without occupying it. All owner-scoped writes recheck the
  observed generation, while admitted Runner cleanup still finishes after a
  takeover. Setup preserves existing rows/history and leaves old active owners
  unknown until explicit recovery. Task outputs add full ownership IDs and
  caller-relative flags without extra normal-loop commands.

- Review handoff prepare/read/save/submit now share complete-Packet validation;
  incomplete inputs no longer reach result-file creation or submission.
  Existing stored Contract constraints remain readable. Target-set failures
  after dispatch report a persistence-unknown outcome while retaining the
  command failure and original error, because target/Runner intent or cleanup
  may already be saved. Normal calls, Runner transactions and gates are unchanged.
- Independent reviewer material display adds a bounded immutable-revision
  inventory of unchanged files, directory discovery, and selected multi-blob
  reads through the safe-Git helper. Generated commands now use its closed
  `material` operations instead of repeating inline Python/import/environment
  code. Full immutable selectors, unchanged byte streams, no-lazy-fetch and
  no-external-diff/textconv behavior remain; no arbitrary Git runner is added.
  Reviewers still choose required
  sources, recover omitted/truncated material and judge the complete target.
  Packet/result storage and final registration gates are unchanged. This is
  retrieval support, not a measured total-token or review-quality claim.
- Schema v23 separates unspecified, required and explicitly not-required
  verification. Omission/whitespace cannot newly complete; an authorized waiver
  needs a bounded reason through existing add/edit/batch input. Task JSON adds
  that reason and `verification_requirement`; the Packet carries the reason.
  Reason changes invalidate the target and evidence. Old done records remain
  historical, while reopened blank work must satisfy the new declaration rule.
  Explicit setup preserves old Task intent, cycle history and Bundle bytes;
  native source-23 Bundles retain format 2. No normal-loop call is added.

- Generated state uses fixed `<governed-project>/.taskgov/` instead of the
  physical package. Explicit offline setup retains the old source, publishes
  its retirement marker and activates a validated candidate; schema and
  business identities do not change merely for the location move. Package
  code/config, ordinary commands and gates retain their boundaries. The
  [setup contract](../setup-state-specification.md#project-state-separation)
  defines phase retry, uncertainty and paired rollback. This is not a claim
  of measured host-permission, token or elapsed-time savings.
- `review result add` accepts bounded versioned JSON for one Task, Contract
  revision, and complete review target. It mechanically validates and saves
  new Receipts and their Findings together or saves none. Missing provenance,
  stale bindings, and duplicates are rejected; individual operations and the
  existing schema-v22 evidence and completion gates remain unchanged.
  The normal no-finding Tier 2 flow uses one result-registration call for both
  reviews; this does not claim a measured reduction in total LLM tokens.
  Its success response now omits repetitive provenance/events with an explicit
  omission notice, retains every new Receipt ID and Finding body/ID, and returns
  the existing review-gate observation on the registration basis. Stored audit
  details and final completion revalidation are unchanged. Consumers of the
  previous full-item JSON must adapt; no additional show/check is required.
- `task context` combines start/resume selection and complete selected-Task
  detail in one read-only operation, without changing selection order, state,
  or verification/review requirements. Individual current/next/show reads
  remain available; the normal Skill flow needs no intermediate read decision.
- Single and batch `task add` now return one `context_preparation` after commit,
  replacing the immediate separate context read when ready. Existing selection
  and validation remain intact; failed preparation is distinct from failed
  registration and must not cause duplicate adds. Existing registration fields
  remain, with this additional success-data field; consumers validating exact
  key sets must accept it. This saves a call, not a measured total-token result.
- Normal Task detail retains complete working information while removing
  duplicate fields and historical Receipt/cycle detail. Explicit `task show
  --audit` preserves the previous bounded audit projection. Stored Evidence,
  validation and completion gates are unchanged.
- Ordinary physical-install, setup/read-only, Task completion with manual
  verification, Evidence JSON, Viewer, backup, and representative recovery
  paths support Windows x86-64, Ubuntu 24.04 x86-64, and macOS 15 Apple Silicon.
  Windows retains Python 3.12/3.14 full-suite qualification; representative
  Linux/macOS checks use Python 3.12. Public Runner execution supports Windows,
  Linux, and macOS under explicit opt-in and the
  [OS-specific Runner contract](../runner-execution-specification.md#approved-os-specific-runner-guarantees). This does not
  change the published v0.10.0 platform boundary or qualify a release.
- The Analyzer runtime is retired; its independent Evidence
  reading/validation capability remains only in repository tests. Existing
  ignored analysis artifacts stay inert and untouched. No report, model, or
  replacement reader runtime is introduced.
- Schema v18 supplies capture-versioned authority and criterion bindings,
  tool-owned Verification Receipt subjects, bounded Review provenance, and
  1,000-character verification admission and retention.
- Schema v19 seals immutable Bundle v1 completion evidence and publishes the
  fixed Evidence JSON v1 projection. Schema v20 preserves those Bundle bytes,
  adds the audit-only Runner storage foundation, seals native Bundle v2 with a
  null Runner observation, and publishes Evidence index v2.
- Schema v21 widens only the frozen Runner gate-basis discriminators. It never
  promotes schema-v20 audit history. One exact-current complete-plan Runner
  pass may supply the Receiptless Runner-observation completion basis; only the
  exact closed no-launch fallback returns to the existing manual Receipt path.
  Every other selected Runner state remains blocking.
- Schema v22 removes only retired Analyzer reservations from the shared
  Evidence schema and current enums. Setup migrates complete v21 state without
  deleting or converting valid rows; new native Bundles use source 22/format 2.
  Retained source-19/20/21 Bundle bytes and digests and the Runner protocol are
  unchanged. Exact-v22 reentry validates without a schema write.
- Viewer snapshot v4 accepts source schemas v5-v25 and validates their
  source-appropriate Task, Contract, Receipt, provenance, Bundle, and Runner
  graph while exposing no Evidence UI.
- The existing `task edit --runner-plan-action` option supports `replace`,
  `rebind`, `detach`, and `disable`. The first absent-Plan `replace` is the
  trusted-local opt-in; `disable` sets the global trust flag false while
  preserving entries. An action-bearing success adds the closed
  `runner_plan_update` with `action` and `updated`, `unchanged`, or `unconfirmed`
  status. Setup never creates or edits the Plan, and authoring never launches
  the Runner. `review target set` remains the sole Runner dispatch and adds the
  closed `verification_route` and nullable
  `blocking_code`. There is no Runner command, new Skill trigger, Analyzer
  gate, network/model invocation, or new public leaf.

## Package And Release-Candidate Boundary

The v0.13.0 package uses the current schema-v25 implementation.
Its release manifest is the exact digest inventory for packaged core files.
Generated state, SQLite files and sidecars, Viewer output, backups, locks,
configuration, caches, logs, secrets, root references, tests, and development
documents remain outside the package artifact. An approved package update
preserves root `.taskgov/` and package-local retirement/recovery material, and
preserves `config/verification-runner.json`, `config/viewer.json`, and
`config/effort-advisory.json` byte-for-byte; release artifacts exclude all
`config/` content.

Archive-inventory acceptance validates the manifest, tracked package tree, and
those exclusions without producing an archive or checksum. The accepted
retired Candidate/LPAC/native code, fixtures, and dedicated tests remain
physically absent from tracked repository and package material, with no tracked
archive or dormant replacement.

Fresh physical installation, the exact legacy v0.1.0/schema-v2 upgrade through
schema v25, current-schema reentry, and paired rollback are offline acceptance
gates. Paired rollback restores one matched legacy package, database, and
managed-artifact set; it never runs old code against schema v25, performs a
reverse migration, mixes generations, or treats a Git checkout alone as a
rollback.

## Privacy And Local-Only Boundary

Verification and review evidence remains bounded and deny-by-default. The
package never retains verification command bodies or arguments, exit codes,
stdout/stderr, stack traces, environment data, logs, exceptions, prompts,
diffs, credentials, arbitrary coverage prose, or debug variants.

The Skill remains project-scoped, local-first, and standard-library-only. It
does not mutate target-project source or Git state, contact a network service,
create an external Issue or PR, launch a browser, or grant publication
authority.

## Candidate Validation Boundary

the offline document and release contracts, exact test-lane partition and full
