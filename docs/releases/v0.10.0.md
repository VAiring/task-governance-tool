# task-governance-tool v0.10.0

`task-governance-tool` 0.10.0 is a project-scoped, local-first Codex Skill and
standard-library Python CLI for resumable task execution with deterministic
state, review, and completion gates.

## Release Identity

- SQLite schema: v16
- Viewer snapshot: v4, accepting source schemas v5-v16
- Public CLI: exactly 20 command leaves
- Supported runtime: Windows with Python 3.12 or newer
- CI workflow/name/job: `.github/workflows/ci.yml` / `CI` / `test`
- CI Python matrix: 3.12 and 3.14
- Remote/repository: `origin` / `VAiring/task-governance-tool`
- Lightweight tag: `v0.10.0`
- Archive: `task-governance-tool-0.10.0.zip`
- Checksum: `task-governance-tool-0.10.0.zip.sha256`

## Highlights

- Stable project identity is separated from its mutable filesystem binding,
  with explicit relocation approval and fixed project-local state.
- Accepted completion cycles remain append-only audit history across reopen,
  while every reopened task still requires fresh current verification, target,
  review, and completion evidence.
- The generated offline Viewer displays the same bounded completion history as
  `task show`, with optional visibility-aware same-file reload and bounded
  browser History state handoff.
- Setup, recovery, Viewer maintenance, and managed backups remain bounded
  same-process local operations. No daemon, network service, Issue sync, or
  automatic target-project mutation is introduced.

## Install, Upgrade, And Rollback

Install one physical package at
`<target-project>/.agents/skills/task-governance-tool`. User-wide copies,
symbolic links, junctions, and alternate state paths are unsupported for
stateful use.

`setup` remains the only initializer and migrator. The release gate rehearses
the supported isolated transition from the legacy v0.1.0/schema-v2 baseline to
v0.10.0/schema v16 before publication.

Rollback means restoring one matched pre-migration package, database, and
managed-artifact compatibility point together. It does not run legacy code
against schema v16, reverse-migrate in place, mix generations, or treat a Git
checkout alone as state rollback. After cutover, corrections use a forward
fix rather than force-updating history, tags, or release assets.

## Review Evidence Trust

Taskgov deterministically evaluates only recorded receipts and findings for
the current review target and generation against the configured gate. Distinct
reviewer keys prove distinct stored strings only; they do not prove distinct
people, LLMs, machines, independent processes, independence, or authenticated
provenance.
